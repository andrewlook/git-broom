# Supply-Chain Checks

This repo uses [cargo-audit](https://github.com/rustsec/rustsec/tree/main/cargo-audit) and [cargo-vet](https://mozilla.github.io/cargo-vet/) to manage dependency security. Both are enforced in CI and available locally.

## cargo-audit

Checks `Cargo.lock` against the [RustSec Advisory Database](https://rustsec.org) for known vulnerabilities, yanked crates, and unmaintained dependencies.

```bash
# install
cargo install cargo-audit --locked

# run
cargo audit
```

Advisories are published independently of your code changes, so CI also runs `cargo audit` on a weekly schedule against `main`.

## cargo-vet

Tracks whether third-party dependencies have been reviewed, either by you or by trusted upstream organizations. Policy lives in the `supply-chain/` directory.

```bash
# install
cargo install cargo-vet --locked

# check current status
cargo vet

# check with locked imports (what CI runs)
cargo vet --locked
```

### After adding or updating a dependency

When you change `Cargo.toml` or `Cargo.lock`, `cargo vet` may fail because the new dependency version isn't covered by existing audits, imports, or exemptions. You have a few options:

```bash
# see what needs attention
cargo vet suggest

# inspect a crate's source
cargo vet inspect <crate> <version>

# after reviewing, certify it
cargo vet certify <crate> <version>

# or add a temporary exemption
cargo vet add-exemption <crate> <version>
```

### Refreshing trusted imports

The repo imports audit sets from Mozilla, Google, Embark Studios, Bytecode Alliance, ISRG, and Zcash. To pull in new audits from these sources:

```bash
# regenerate imports.lock with latest upstream audits
cargo vet

# then prune any exemptions that are now covered
cargo vet prune
```

Commit the updated `supply-chain/` files.

### Key files

| File | Purpose |
|------|---------|
| `supply-chain/config.toml` | Imported audit sources, exemptions, and policy criteria |
| `supply-chain/audits.toml` | Local audits recorded by maintainers |
| `supply-chain/imports.lock` | Locked snapshot of imported audits (regenerated by `cargo vet`) |

## CI behavior

The supply-chain workflow (`.github/workflows/supply-chain.yml`) runs:

| Check | PRs | Push to main | Weekly schedule |
|-------|-----|-------------|-----------------|
| `cargo audit` | yes | yes | yes |
| `cargo vet --locked` | yes | yes | no |

The `--locked` flag ensures CI uses the committed `imports.lock` rather than fetching fresh imports, so builds are reproducible.

## What's not in pre-commit

Advisory and audit checks are deliberately excluded from `.githooks/pre-commit`. They depend on network-fetched databases that change independently of the code being committed. The pre-commit hook stays fast and deterministic (format + lint only).
